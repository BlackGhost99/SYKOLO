# Expédition YEM Parents — pilote gratuit Supabase Cron

Le serveur existant reste la seule instance qui détient les secrets Firebase et la clé de chiffrement. Ne pas dupliquer ces secrets. La route POST /internal/yem-parent-push ne reconnaît ni cookie ni rôle d'école. Elle consomme un ticket à usage unique, généré dans Postgres (244 bits aléatoires environ), expiration 4 min, empreinte SHA-256 seulement dans une table privée, bail d'exécution 3 min. SQL paramétré et pas de données scolaires dans la requête HTTP. Le ticket transitoire est dans la file pg_net, non lisible par les rôles publics.

Déployer le code **avant** d'appliquer `deploy/supabase-parent-push-pilot.sql` dans le projet YEM exclusivement, avec la connexion opérateur propriétaire de la base (le rôle Django doit avoir accès à la table privée; vérifier sans divulguer de secret). Le code refuse une requête si les paramètres FCM actuels ne sont pas présents. Ne pas activer un cron Render en parallèle. Vérifier les droits de schéma/tables/fonction/net, le job cron et les réponses HTTP uniquement par code de statut, sans lire les en-têtes. Une tentative invalide, GET, un ticket expiré ou réutilisé ne doit jamais expédier. Pour stopper : SELECT cron.unschedule('yem-parents-push-pilot');. Ne pas supprimer les extensions partagées.

Politique de pilote : vérification SQL toutes les 5 minutes, **pas d'appel HTTP sans appareil actif**, déclenchement si message durable à expédier/reprendre ; balayage horaire pour les sources calculées (admissions et finances). Limite 25 appareils actifs, 12 nouvelles livraisons et 3 expéditions par passage, timeout FCM 5 s, bail anti-chevauchement. Le serveur Render Free peut dormir et une requête peut échouer au réveil ; le ticket expire et une nouvelle tentative intervient au passage suivant. Les heures gratuites sont partagées entre services. Surveiller les quotas et arrêter le pilote si la consommation devient trop élevée ; ne pas détourner le cron en keep-alive. Pas de garantie de temps réel ou de capacité commerciale. Au-delà du pilote passer à un expéditeur dédié, pas simplement relever les limites. Une réception sur matériel Android réel reste indispensable. Les notifications restent génériques; les données restent dans YEM. La commande de gestion inchangée est utilisable pour un vrai worker privé.
